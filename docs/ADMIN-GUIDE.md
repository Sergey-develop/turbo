# Работа с админкой

Админка: https://turbo-rave.aopopo11.workers.dev/admin

## Приглашённые и заявки

«Приглашённые» — список организатора до регистрации человека. Здесь есть добавление вручную и CSV UTF-8 (запятая или точка с запятой), шаблон файла, предпросмотр, проверка и пропуск повторных email. До 100 гостей за один импорт. Обязательны Фамилия / Имя / Email; компания, должность и телефон необязательны. Импорт не отправляет письма, не создаёт согласие гостя и не занимает места среди подтверждённых заявок. После заполнения гостем формы его статус отображается в списке по совпадению email. Удаление приглашённого не удаляет его заявку.

«Заявки» — реальные регистрации гостей. По 50 строк на странице; показан диапазон и общее количество страниц. Изменения фильтров вступают в силу по кнопке «Применить», она возвращает на первую страницу. «Сбросить фильтры» очищает все фильтры. Экспорт использует применённые фильтры, захватывает все страницы (до 10 000 записей) и только разрешённые в настройках поля. Без фильтров выгружаются все заявки. Введённый, но не применённый фильтр на экспорт не влияет.

## Статусы и письма

| Статус заявки | Смысл |
| --- | --- |
| pending | Ожидает решения |
| approved | Участие подтверждено |
| waitlisted | Лист ожидания |
| rejected | Отказ |
| cancelled | Отменено гостем или организатором |

registered — тип письма о получении заявки, а не статус гостя. Для каждой новой регистрации создаётся registered. При одобрении создаётся approved; при отказе — rejected, если включена настройка писем об отказе. В режиме open новая заявка сразу подтверждена и создаёт registered и approved. В режиме moderated она pending, в waitlist — waitlisted, в closed форма не принимает заявки. Отмена не создаёт письмо. При отмене и отказе ещё не отправленные письма аннулируются; фактически отправленные письма отозвать нельзя.

Создание задания не означает отправку. В этой сборке нет фонового расписания: обработка выполняется кнопкой «Обработать очередь» (или защищённым техническим endpoint при отдельно подключённом планировщике).

## Контент и публикации

В «Контенте» сохраняется черновик, затем его можно посмотреть и опубликовать. История фиксирует публикации с момента обновления админки; исходное опубликованное состояние тоже сохранено. Старую историю до этого обновления восстановить нельзя. В интерфейсе показаны последние 100 публикаций. «Посмотреть» показывает содержимое версии. «Восстановить в черновик» не меняет публичный сайт: после восстановления нужно проверить и опубликовать. Защита по версии предотвращает перезапись параллельных изменений другим редактором. Снимки включены в резервную копию.

## Подключение почты

Провайдер — Resend. Подключение пока пропущено по просьбе владельца, реальная отправка выключена.

Для будущего подключения: подтвердить домен в Resend, установить MAIL_PROVIDER=resend и RESEND_API_KEY (секрет Cloudflare Worker); PUBLIC_ORIGIN — адрес сайта для ссылок в письмах. Адрес отправителя указывается в «Настройках → Адрес отправителя писем» (он имеет приоритет над MAIL_FROM из окружения). Затем включается «Разрешить отправку писем». Фактическое состояние, наличие ключа и адрес отправителя видны в «Очереди писем». Ключ в интерфейсе не отображается.

## Очередь, доставка и повторы

«Обработать очередь» делает до 10 попыток готовых заданий. После ошибки время следующей попытки увеличивается: 2, 4, 8, 16 минут; автоматических попыток не более пяти и лишь при следующем запуске обработки. Незавершённое задание после истечения двухминутной аренды может быть восстановлено при обработке в пределах безопасного окна. Старые неоднозначные попытки после 23 часов блокируются для ручной сверки.

«Повторить попытку» — то же задание с тем же ключом и замороженным запросом провайдеру. Это позволяет избежать дубля в окне идемпотентности Resend. «Отправить ещё раз» создаёт новое задание по сохранённому тексту шаблона с актуальными данными гостя. Это новое письмо, поэтому требуется явное подтверждение; для старой ошибочной/зависшей отправки сначала нужна сверка в Resend. Нажатие этих кнопок только ставит письмо в очередь, отправка — отдельной обработкой. Отменённые письма не возобновляются. Изменение шаблона не меняет уже созданные задания.

«Принято провайдером» — успешный ответ Resend на передачу письма, не доказательство доставки. В строке видны адрес, тип письма, число попыток, ошибка, время следующей попытки, ID провайдера и время последней проверки доставки. «Проверить доставку» запрашивает актуальный last_event в Resend. Проверка ручная, webhook не подключён. delivered означает приём сервером получателя, не гарантирует попадание во «Входящие» или прочтение.

При ошибке проверьте причину (например HTTP 401 — ключ, 403 — права/домен, 429 — лимит), исправьте подключение и верните письмо в очередь. При зависшей или старой неоднозначной отправке сначала найдите письмо в Resend → Emails по ID провайдера либо email гостя. Повторная отправка без сверки может создать дубль.

Приглашённые включены в резервную копию и очистку по сроку хранения; история публикаций и почтовые операции фиксируются в журнале.
