# Настройки, требующие бизнес-утверждения

Решения ниже — реализованные конфигурируемые допущения по поручению заказчика, а не подтверждённые правила мероприятия.

| Вопрос | Реализация и безопасное начальное значение |
| --- | --- |
| Четыре режима | `open`: сразу approved при наличии места; `moderated`: pending; `waitlist`: waitlisted; `closed`: отказ до записи. Начальный режим closed. |
| Вместимость | 200 approved. Pending/waitlisted не занимают место. Уменьшить вместимость ниже числа approved нельзя. |
| Лимит заявок | Не утверждён: `null`, без бизнес-лимита. Сервер ограничивает частоту запросов: 10 попыток/час на хеш адреса или платформенной личности. Лимит maxApplications считает все сохранившиеся заявки, включая отменённые. |
| Полный зал в open | HTTP 409 без создания заявки. Автоматического перевода в лист ожидания нет. |
| Отмена/отказ | Освобождают место. Автоматического продвижения очереди нет. Отклонённая/отменённая заявка не возобновляется; повторное одобрение терминального статуса запрещено. |
| Повторная регистрация | Одна запись на нормализованный email, без автоматического объединения разных гостей. Повтор той же операции определяется Idempotency-Key и хешем содержимого. Для изменений после отправки нужен организатор. |
| Кто одобряет | admin, manager. editor редактирует контент; analyst видит агрегаты; scanner отмечает проход одобренных гостей без списка ПДн. |
| Согласия | Обязательное согласие отдельно от добровольной рассылки. Тексты, основания и версии задаются в кабинете. Пока legalApproved=false, сервер не принимает заявки. Тестовые тексты нельзя утверждать в production. |
| Почта | Отправка выключена. Поддержан Resend; нужны проверенный отправитель и ключ. Отказы по умолчанию без письма. Шаблоны являются редактируемыми стартовыми текстами. |
| Фото и контент | Исходный контент взят из макета, включая повторяющиеся портреты и имена. Он не считается утверждённой программой. Редактор может заменить его и опубликовать. |
| Хостинг и ПДн | D1/R2 провиженит Sites. Географию и правовое основание такого размещения ещё должен подтвердить организатор. Данные реальных гостей до этого не собирать. |
| Хранение | retentionDays=null: удаление выключено до утверждения срока. Администратор видит количество просроченных записей и отдельно запускает удаление. Автоматическое расписание ещё требует настройки. |
| Проход | Реализован, по умолчанию выключен. Это отметка по ID и версии заявки; QR-сканер и турникеты не интегрированы. |

## Граница гарантии писем

Заявка и задания очереди создаются SQL-триггерами в одной транзакции. При отказе вставки задания заявка также откатывается. Уже созданное задание хранит снимок шаблона; последующие правки шаблона действуют на новые задания.

Обработчик атомарно арендует queued-задание. Повторная отправка использует тот же ключ идемпотентности Resend. При сбое выполняется до 5 попыток с задержкой. Неоднозначные sending старше 23 часов не переотправляются автоматически, пока оператор не сверит их с провайдером.

Отмена снимает queued/failed задания. Перед отправкой повторно проверяется статус гостя. Письмо, уже переданное провайдеру или попавшее в короткое окно между проверкой статуса и сетевой отправкой, нельзя отозвать транзакцией D1. Интерфейс не обещает обратного.

Автоматический запуск /api/internal/mail/dispatch требует внешнего планировщика и platform-level доступа к приватному Sites. JOB_RUNNER_SECRET не заменяет вход на приватный сайт. Без настроенного планировщика очередь можно обрабатывать кнопкой в кабинете; скрытого обещания фоновой доставки нет.
