# Под капотом — Турбо-рейв

## Размещение на GitHub Pages и Cloudflare

Ветка `main` публикует лендинг через GitHub Actions на `https://sergey-develop.github.io/turbo/`. Публичный API и панель `/admin` размещаются отдельно на Cloudflare Worker `turbo-rave.aopopo11.workers.dev`; форма делает запросы напрямую к этому API. CORS разрешает публичные endpoints только для указанного GitHub origin; административные запросы остаются на домене Worker.

Сборка и публикация Worker: `npx vite build --config vite.cloudflare.config.ts`, затем `npx wrangler deploy --config dist/server/wrangler.json`. Для статической сборки: `npx vite build --config vite.github.config.ts`, затем `node scripts/github-pages.mjs`. Не заменяйте GitHub-сборкой серверный `dist`.

В Cloudflare secrets заданы `ADMIN_USERNAME`, `ADMIN_PASSWORD_VERIFIER`, `CANCEL_SECRET`, `PUBLIC_ORIGIN`. Пароли и значения secrets не хранятся в репозитории. Учётные данные владельца сохранены локально в `C:\Users\sprin\Desktop\турбопушка\admin-login.txt`; берегите этот файл. Пароль сгенерирован случайно, проверяется сервером; сессии хранятся в D1 и отзываются при выходе. Сейчас предусмотрена одна учётная запись администратора; отдельные аккаунты и роли сотрудников для password-режима не подключены.

Новые фотографии загружать пока нельзя: R2 не включён. Почтовый провайдер и автоматический запуск рассылки не подключены. Регистрация закрыта до утверждения текстов, правовых оснований и места хранения данных. Новая D1 создана в регионе Восточной Европы; перед использованием для ПДн требуется согласование региона. Миграции `0000_registration.sql` и `0001_password_sessions.sql` применены к новой базе напрямую; перед дальнейшим использованием автоматического мигратора необходимо привести его журнал в соответствие, не применяя первую миграцию повторно. Данные прежнего сайта автоматически не переносились.

Vue 3 + TypeScript + SCSS, сервер Cloudflare Workers, постоянные данные D1, фотографии R2. Существующий лендинг и его анимации сохранены. Панель организатора: `/admin`; отмена гостем: `/cancel`.

## Установка и запуск

Node.js >=22.13. Команды из папки `C:\Users\sprin\Desktop\турбопушка\landing`:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run db:migrate
npm.cmd run dev -- --port 5175
```

Локальный вход: `http://127.0.0.1:5175/signin-with-chatgpt?return_to=/admin`. В Настройках выполните инициализацию. По умолчанию приём закрыт, отправка почты отключена. Только для локального теста разрешён mock-вход; в production личность устанавливает Sites.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
# Отдельно, при работающем локальном сервере:
npm.cmd run test:browser
```

`test:browser` меняет локальную БД, настройки и черновик тестовыми данными. Production URL запрещён самим тестом.

## Возможности

- Заявки: серверная валидация, UTM, идемпотентность, нормализованный уникальный email, поиск, фильтры, пагинация, одобрение/отказ/отмена, CSV с разрешённым перечнем полей.
- Вместимость: SQL-триггер атомарно проверяет каждое одобрение. Тест использует два настоящих конкурентных SQLite-соединения.
- Режимы: open/moderated/waitlist/closed. Режимы и лимиты исполняет сервер и БД, не клиентский переключатель.
- Письма: transactional outbox, снимки шаблонов, аренда задания, стабильный provider idempotency key, повторные попытки, тест себе и ручной обработчик. Автоматический production scheduler ещё требует настройки.
- CMS: формы программы, спикеров/фото, FAQ и текстов; черновик, защищённый предпросмотр, публикация с проверкой версии.
- Роли admin/manager/editor/analyst/scanner на сервере. Журнал, аналитика из БД, отметка прохода, хранение данных и экспорт резервной копии.

## Основные файлы

- `server/index.ts` — API, RBAC, регистрация, CMS, почтовый обработчик, медиа, журнал, CSV и резервный снимок.
- `server/defaults.ts` — стартовые настройки, права и шаблоны.
- `drizzle/0000_registration.sql`, `drizzle/meta/_journal.json` — схема, ограничения, триггеры и журнал миграций; после применения не менять.
- `src/AdminApp.vue`, `src/CancelPage.vue`, `src/api.ts`, `src/cms.ts` — кабинет, отмена, API-клиент и CMS.
- `src/components/*` — подключение формы, редактируемого контента и изображений к прежнему дизайну.
- `vite.config.ts`, `scripts/vite/sites-vite-plugin.ts` — Vue и Worker build с интеграцией Sites.
- `tests/api.test.mjs`, `tests/concurrent-worker.mjs`, `tests/browser.mjs` — серверные и сквозные тесты.
- `.env.example`, `docs/openapi.json`, `docs/ASSUMPTIONS.md`, `docs/OPERATIONS.md` — настройки, API, допущения и эксплуатация.
